🗒 今天的四個問題：VLA 是什麼？動作怎麼輸出？資料從哪來？怎麼跑得夠快？
O1 · 說出 VLA 的定義，以及它和 LLM / VLM 的關係

從 LLM → VLM → VLA

LLM文字進 → 文字出
VLM影像 + 文字進 → 文字出
VLA影像 + 指令進 → 機器人動作出
  • VLA 是把 VLM 微調成直接輸出機器人動作的模型vla#1
  • 輸入相機影像與語言指令，輸出下一步（或下一段）動作vla#2
  • 這個名稱由 RT-2 提出rt2#1
  • 像讓一個很會看圖說話的人，改成看圖動手
名詞小卡

O1 · 說出 VLA 的定義，以及它和 LLM / VLM 的關係

為什麼要借用 VLM？

  • VLM 從網路圖文學到的知識，能幫機器人理解沒看過的物體與指令vla#3
  • RT-2 聽得懂「把東西放到某個數字上」這種機器人資料沒有的指令rt2#9
  • 還會簡單推理：挑最小的物體、拿石頭當鐵鎚rt2#9
  • 未見情境平均 62，舊的 policy RT-1 只有 32，約 2 倍rt2#7
  • 限制：網路資料不會教機器人新動作rt2#11
名詞小卡
policy機器人的決策函式：看到當下狀態 → 決定下一個動作
🗒 知識會轉移，但「動作技能」還是要靠機器人資料。
O1 · 說出 VLA 的定義，以及它和 LLM / VLM 的關係

誰算 VLA？誰不算？

  • RT-1：用 Transformer 直接學動作，但沒有網路規模預訓練的 VLMvla#4
  • Octo：通用機器人 policy，但不是建在預訓練 VLM 上vla#5octo#2
  • RT-2、OpenVLA、π0：都建在預訓練 VLM 上 → 屬於 VLAvla#6
  • 判斷關鍵：骨幹是不是一個先在網路圖文上訓練過的 VLMvla#6vla#4
O2 · 理解動作怎麼變成模型輸出：離散 token vs 連續動作

動作怎麼變成 token？

  • RT-2 的動作：6-DoF 末端位移與旋轉 + 夾爪 + 終止指令rt2#3
  • 每個連續維度切成 256 個 bin，一個動作變成 8 個整數rt2#3
  • 整數寫成 token，就能沿用語言模型的 next-token 預測訓練action-representation#3
  • OpenVLA：bin 範圍取第 1–99 百分位，並覆寫最少用的 256 個 tokenopenvla#3
  • 就像把連續的溫度四捨五入成刻度，再把刻度當單字
名詞小卡
DoFDegree of Freedom 自由度；6-DoF = 3 個位移 + 3 個旋轉
O2 · 理解動作怎麼變成模型輸出：離散 token vs 連續動作

另一條路：diffusion 與 flow matching

  • Octo：diffusion action head 經 20 個去噪步，產生連續動作 chunkcontinuous-action-heads#1
  • π0：PaliGemma 旁掛 300M 的 action expert，用 flow matching 產生連續動作continuous-action-heads#2
  • 直覺：從雜訊一步步修正成動作，能表示「多種合理做法」推論continuous-action-heads#3
  • 離散路線仍有競爭力：OpenVLA 微調後比 Diffusion Policy 高 20.4%continuous-action-heads#4
名詞小卡
diffusion從隨機雜訊出發、反覆去噪來生成資料（影像生成常用）
flow matching學一個把雜訊「流」向資料的速度場，和 diffusion 是近親
action chunk模型一次預測的一整段未來動作

O3 · 知道 VLA 的資料從哪來：跨機體資料與 co-fine-tuning

資料從哪來？跨 embodiment 學習

  • Open X-Embodiment：21 個機構合作、22 種機器人oxe#1
  • 涵蓋 527 種技能（160,266 個任務）oxe#2
  • RT-X 用別台機器人的資料訓練，各台都變強oxe#4
  • Octo 挑 800k 條、OpenVLA 挑 970k 條軌跡預訓練cross-embodiment#4
  • RT-1 的結論：資料多樣性比資料量更重要cross-embodiment#6
名詞小卡
embodiment機器人的「身體」：手臂型號、感測器、動作空間都不同
正遷移positive transfer：學 A 的資料，反而讓 B 也變好
🗒 類比：學過很多樂器的人學新樂器更快。
O3 · 知道 VLA 的資料從哪來：跨機體資料與 co-fine-tuning

Co-fine-tuning：別讓 VLM 失憶

  • 微調時同時放機器人軌跡與網路圖文資料（如 VQA）co-fine-tuning#1
  • RT-2 中機器人資料約佔 50%（PaLI-X）與 66%（PaLM-E）co-fine-tuning#2
  • 55B 模型泛化分數：co-fine-tune 63 vs 只用機器人資料 52co-fine-tuning#3
  • 只餵機器人資料，VLM 可能忘掉網路常識推論co-fine-tuning#4
名詞小卡
co-fine-tuning微調時把新任務資料和原本的網路資料混在一起訓練
O4 · 理解為什麼需要 action chunking 才能高頻控制

大模型太慢？Action chunking

  • 一次輸出未來好幾步的動作，而不是每次只輸出一步action-chunking#1
  • RT-2 55B 每步都跑大模型，只有 1-3 Hz；OpenVLA 約 6 Hzaction-chunking#3
  • π0 一次輸出 50 步，控制頻率可達 50 Hzaction-chunking#2
  • 把「思考頻率」和「控制頻率」分開推論action-chunking#4
名詞小卡
控制頻率每秒送給馬達幾次指令（Hz）；越高動作越順
