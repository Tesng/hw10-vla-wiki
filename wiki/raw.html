RT-1: Robotics Transformer for Real-World Control at Scale (2022)

id: rt1｜https://arxiv.org/abs/2212.06817

RT-1 (Brohan et al., 2022) — source extract

  • Dataset: over 130k real-robot demonstrations, over 700 distinct task instructions, collected with 13 robots over 17 months.
  • Model: ~35M parameters. FiLM-conditioned EfficientNet-B3 (conditioned on the language instruction) → TokenLearner → decoder-only Transformer (8 self-attention layers, 19M params). Image tokenizer 16M params.
  • Each image yields 81 visual tokens, compressed to 8 by TokenLearner; a history of 6 images gives 48 tokens.
  • Actions: 11 action dimensions (7 arm, 3 base, 1 mode switch); each dimension discretized into 256 bins → actions are predicted as discrete tokens.
  • Control: 3 Hz closed-loop, inference budget under 100 ms.
  • Results: 97% success on seen training instructions; 76% on unseen tasks, 83% with distractors, 59% with new backgrounds.
  • Finding: "data diversity is more essential than data quantity."
  • Within SayCan long-horizon planning: 67% execution success; plans with as many as 50 steps.

RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control (2023)

id: rt2｜https://arxiv.org/abs/2307.15818

RT-2 (Zitkovich / Brohan et al., 2023) — source extract

  • Coins the term vision-language-action (VLA) model: a VLM fine-tuned so that it outputs robot actions.
  • Key idea: express robot actions as text tokens and put them directly into the training set of a vision-language model.
  • Action space: 6-DoF end-effector position + rotation displacement, gripper extension, and a discrete terminate command. Continuous dims discretized into 256 uniform bins → each action = 8 integers.
  • Token mapping: PaLI-X has a unique token for every integer up to 1000, so bins map to integer tokens; PaLM-E has no such tokens, so its 256 least-frequently-used tokens are overwritten as action tokens.
  • Models: RT-2-PaLI-X (5B and 55B), RT-2-PaLM-E (12B).
  • Co-fine-tuning: robot trajectories mixed with Internet-scale vision-language data (e.g. VQA). Robot data ≈50% of the PaLI-X mixture, ≈66% of the PaLM-E mixture. Co-fine-tuned 55B averages 63 on generalization vs 52 fine-tuned-only.
  • Unseen-scenario averages (Table 4): RT-2-PaLI-X-55B 62, RT-2-PaLM-E-12B 62, MOO 35, RT-1 32 → about 2x over RT-1 and MOO.
  • About 6,000 evaluation trials.
  • Emergent capabilities: novel objects, commands not in robot data (place object on a number/icon), rudimentary reasoning (smallest/largest object), chain-of-thought multi-stage reasoning (rock as improvised hammer; energy drink for a tired person).
  • Inference: 55B runs at 1-3 Hz, 5B at ~5 Hz, served from a multi-TPU cloud service queried over the network.
  • Limitations: robot does not learn new motions from web data — skills stay "limited to the distribution of skills seen in the robot data"; high compute cost; suggests quantization/distillation.

Open X-Embodiment: Robotic Learning Datasets and RT-X Models (2023)

id: oxe｜https://arxiv.org/abs/2310.08864

Open X-Embodiment (OXE, 2023) — source extract

  • A pooled dataset from 22 different robots, assembled through a collaboration of 21 institutions.
  • Demonstrates 527 skills (160,266 tasks).
  • Datasets released in a standardized data format, together with models.
  • RT-X: high-capacity models (RT-1-X, RT-2-X) trained on this mixture "exhibit positive transfer and improve the capabilities of multiple robots" — i.e. training on other robots' data helps each robot.
  • Cross-embodiment learning: one policy trained across many robot bodies.

Octo: An Open-Source Generalist Robot Policy (2024)

id: octo｜https://arxiv.org/abs/2405.12213

Octo (Octo Model Team, 2024) — source extract

  • Sizes: Octo-Small 27M, Octo-Base 93M parameters. Not built on a pre-trained VLM (a generalist policy, not a VLA in the RT-2 sense).
  • Pretraining: 800k trajectories curated from 25 datasets of Open X-Embodiment.
  • Architecture: transformer backbone with learned readout tokens (like BERT's [CLS]); block-wise masked attention so inputs/outputs can be added or removed at fine-tuning time (flexible observation and action spaces).
  • Action output: diffusion action head predicting a chunk of consecutive actions (20 diffusion steps) — continuous actions, not discrete tokens.
  • Task conditioning: language instruction (t5-base encoder) or goal image.
  • Zero-shot: 29% higher success than RT-1-X (35M); performed similarly to RT-2-X (55B) on WidowX and RT-1 robot tasks.
  • Fine-tuning: ~5 hours on a single NVIDIA A5000 consumer GPU with ~100 demonstrations; outperforms next best baseline by 52% on average across six setups.
  • Pretraining compute: 300k steps, batch 2048, TPU v4-128 pod, 14 hours. Evaluated on 9 robot platforms across 4 institutions.

OpenVLA: An Open-Source Vision-Language-Action Model (2024)

id: openvla｜https://arxiv.org/abs/2406.09246

OpenVLA (Kim et al., 2024) — source extract

  • 7B-parameter open-source VLA. Backbone: Prismatic-7B = 600M-parameter visual encoder fusing SigLIP + DINOv2 features, 2-layer MLP projector, Llama 2 7B language model.
  • Training data: 970k robot manipulation trajectories from Open X-Embodiment (curated subset of >2M).
  • Action tokenization: each action dimension discretized separately into 256 bins; bin widths uniformly divide the interval between the 1st and 99th quantile of training actions (robust to outliers). Bins are mapped onto the 256 least-used tokens of the Llama tokenizer (overwritten).
  • Compute: 64 A100 GPUs for 14 days (21,500 A100-hours), batch size 2048.
  • Results: outperforms RT-2-X (55B) by 16.5% absolute task success with 7x fewer parameters, across 29 tasks and multiple embodiments. Fine-tuned OpenVLA beats Diffusion Policy by 20.4%.
  • Fine-tuning: LoRA on all linear layers, rank 32, ~1.4% of params (97.6M); 68.2% vs 69.7% full fine-tuning; 10-15 hours on a single A100 (8x less compute).
  • Inference: ~6 Hz on one RTX 4090 in bfloat16, ~15GB GPU memory; quantization keeps success rate.

π0: A Vision-Language-Action Flow Model for General Robot Control (2024)

id: pi0｜https://arxiv.org/abs/2410.24164

π0 (Physical Intelligence, 2024) — source extract

  • Flow-matching architecture built on top of a pre-trained VLM: PaliGemma (open-source 3B VLM) + a 300M-parameter "action expert" (total 3.3B).
  • Action expert: separate set of weights for robot state and action tokens, trained with conditional flow matching → continuous actions (no discretization).
  • Action chunks of H=50 future actions; control up to 50 Hz for dexterous tasks such as laundry folding.
  • Data: over 10,000 hours of robot data; own data 903M timesteps (106M single-arm, 797M dual-arm); ~9.1% of mix is open-source data (OXE, Bridge v2, DROID). 7 robot configurations, 68 tasks.
  • Recipe: pre-training on broad diverse data → general base model; post-training on smaller curated high-quality data for specific tasks (≈5 hours for simplest tasks, 100+ hours for most complex).
  • Example tasks: laundry folding, table bussing, box assembly, egg packing, grocery bagging.

FAST: Efficient Action Tokenization for Vision-Language-Action Models (2025)

id: fast｜https://arxiv.org/abs/2501.09747

FAST (Pertsch et al., Physical Intelligence, 2025) — source extract

  • Problem: prior VLAs discretize each action dimension at each timestep into one of 256 bins. At high control frequency, consecutive action tokens are highly correlated, so models reach low token prediction loss with trivial mappings and get stuck in poor local optima; marginal information per token approaches zero as frequency increases.
  • FAST = Frequency-space Action Sequence Tokenization: normalize each dimension (1st/99th quantile to [-1, 1]) → discrete cosine transform (DCT) per dimension → scale and round coefficients (default scale 10) → flatten low frequencies first → byte-pair encoding (BPE, default vocabulary 1024).
  • Compression for 1-second chunks (naive vs FAST tokens): BridgeV2 5 Hz 35 vs 20; DROID 15 Hz 105 vs 29; Table Bussing 20 Hz 140 vs 28; T-Shirt Folding 50 Hz 700 vs 53 (13.2x). Roughly 30 tokens per chunk per arm, largely independent of control frequency.
  • FAST+ universal tokenizer trained on about 1M one-second action chunks from diverse robots.
  • π0-FAST (autoregressive, discrete tokens) matches diffusion π0 on evaluated tasks including laundry folding; reaches high Table Bussing performance with 3x fewer training steps; up to 5x less training time (GPU hours).
  • Trade-off: inference about 750 ms per chunk vs about 100 ms for diffusion π0 on an NVIDIA 4090.
  • Scales to 10k hours of robot data; first zero-shot DROID evaluation in unseen environments (16 tasks, 44 trials).
